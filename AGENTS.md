# Правила работы с проектом

- Все изменения в коде выполнять только в отдельной ветке.
- Перед началом правок кода обсудить их с пользователем.
- Управлять экраном телефона только после явной команды пользователя.
- Фраза «пуш в мастер» означает пуш в локальный `master`.
- Пуш в `master` на `origin` выполнять только после явной команды «пуш в мастер/оргин».

## Локализация Android

- Эталон локализации — ресурсы `app/src/main/res/values/strings*.xml`.
- Список поддерживаемых локалей определяется `app/src/main/res/xml/locales_config.xml`.
- Ресурсы каждой локали раскладывать по тем же тематическим XML-файлам, что и одноимённые ресурсы в `values`. Пустые файлы создавать не нужно.
- Ресурсы с `translatable="false"` переводить и копировать в каталоги локалей не требуется.
- Нельзя молча оставлять английский fallback для переводимых ресурсов. Любое временное исключение нужно явно согласовать с пользователем и документировать.
- При переносе ресурсов между файлами не менять их имена и значения.
- После добавления или изменения локали обязательно запускать `powershell -NoProfile -ExecutionPolicy Bypass -File tools/check_localizations.ps1`. Параметр действует только для этого процесса и не меняет системную политику Windows.
- Проверка должна подтверждать:
  - отсутствие потерянных, лишних и дублирующихся ключей;
  - совпадение типов ресурсов и количества элементов массивов;
  - наличие обязательной формы `other` и отсутствие повторяющихся форм у `plurals`;
  - совпадение форматных аргументов (`%s`, `%d`, `%1$s` и подобных);
  - соответствие тематического файла английскому эталону;
  - соответствие каталогов локалей списку `locales_config.xml`;
  - корректность XML.
- После проверки показать пользователю сводку по каждой локали и отдельно перечислить найденные проблемы. Не исправлять и не переводить строки автоматически без согласования.
